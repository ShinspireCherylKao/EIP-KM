## 一、文件庫管理

對應導航：近期存取 / 共享部門 
對應頁面：`km-recent.html`、`km-my-org.html`

### 1.1 近期存取（km-recent.html）

#### 頁面佈局
- 雙欄佈局：左側資料夾導航面板 + 右側檔案列表，最小寬度為800，維持雙欄是水平的
- 容器與視窗邊緣保持固定間距（對齊 `.km-nav` 的 `margin: 0 24px`），不設 `max-width` 置中
- 左側面板寬度：佔 25%，最小 220px，最大 360px，隨視窗大小自適應
- 右側列表：自動填滿剩餘空間（`flex: 1`）
- 整體高度：`calc(100vh - 200px)`，最小高度 500px

#### 左側導航面板
- 搜尋框：支援即時搜尋資料夾名稱（輸入即過濾）
- 「快速檢視」區塊：我的收藏、垃圾桶
- 「最近資料夾」區塊：顯示最近瀏覽過的資料夾

#### 列表與分頁
- 不採用分頁（Pagination）設計，一次全部顯示
- 無筆數上限，載入該資料夾所有檔案
- 排序：子資料夾排在檔案前面，依資料夾名稱正排序、檔案名稱正排序顯示
- 表格欄位：檔案名稱 / 更新日期 / 操作 
- 資料夾操作項目功能有： 收藏 / 設定 / 移到垃圾桶
- 檔案操作項目功能有： 收藏 / 預覽/ 下載/ 更多
- 檔案操作項目「更多」中的功能有：/ 重新命名 / 移到垃圾桶

#### 資料顯示
- 資料夾截斷規則：完整顯示全名
- 資料夾空狀態文字：
  - 資料夾無檔案：「此資料夾沒有檔案」
- 時間格式：`YYYY-MM-DD`
- 檔名截斷規則：完整顯示全名含副檔名


#### 檔案圖示
- `.pdf` → `fa-file-pdf`
- `.doc / .docx` → `fa-file-word`
- `.xls / .xlsx` → `fa-file-excel`
- `.ppt / .pptx` → `fa-file-powerpoint`
- 其他 → `fa-file`


#### 資料夾操作權限
- Admin 管理者  (查看/編輯/上傳/下載/刪除)
- Editor 編輯者 (查看/編輯/上傳/下載)
- Viewer 檢視者 (查看/下載)

#### 檔案操作權限
- Admin 管理者 (查看/編輯/下載/刪除)
- Editor 編輯者 (查看/編輯/下載)
- Viewer 檢視者 (查看/下載)	

#### 檔案操作
- 收藏：收藏 / 取消收藏切換
- 線上檢視：僅 `pdf / png / jpg / jpeg` 可檢視，其他顯示 disabled 圖示並提示「此檔案無法線上檢視，請下載後開啟」
- 下載：使用者需具有檢視者或編輯者或管理者身份權限時可下載
- 更多選單：共用 / 修改檔名 / 移到垃圾桶
- 修改檔名：使用 Modal 輸入，同資料夾名稱不可重名
  - 輸入同名資料夾需警示「資料夾不可重名」

#### 資料夾操作
- 新增資料夾：Modal 輸入名稱，同層不可重名
- 重新命名資料夾：使用者需具有編輯者或管理者身份
- 單一資料夾最多可包含 10,000 個項目 
   - 包含：
   - 檔案（files）
   - 子資料夾（folders）
- 資料夾命名規則：
  - 最多 **255 個字元**（characters）
  - 支援 Unicode（中文、日文 等皆可）
  - 不可包含以下特殊字元：`\ / : * ? " < > |`
  - 不可為空字串
  - 不能只有空白字元
- 刪除資料夾：使用者需具有管理者身份（不具備時隱藏按鈕），confirm 確認後刪除本身 + 所有子資料夾 + 子檔案
- 資料夾收藏：可收藏 / 取消收藏
- 資料夾權限設定：設定人員權限 (查看/新增/編輯/上傳/刪除)


#### 我的收藏
- 進入檢視時：僅有列表，隱藏「上傳檔案」和「新增資料夾」按鈕

#### 垃圾桶
- 提示文字：「垃圾桶中的項目會在 **30 天**後永久刪除」
- 垃圾桶中顯示：檔名（灰色）、原位置、刪除日期
- 操作：永久刪除（confirm 確認）/ 清空垃圾桶（confirm 確認後全部清除）
- 移到垃圾桶時：同步從收藏 + 最近存取中移除
- 進入垃圾桶檢視時：隱藏「上傳檔案」和「新增資料夾」按鈕
- 只列出有刪除權限的檔案

#### 資料夾共用功能
- 共用對象選擇：依人員設定權限等級
- 共用權限等級：參閱 #### 資料夾操作權限

#### 檔案共用功能
- 共用對象選擇：部門 / 人員只能擇一，切換時需 confirm 確認才清空已選
- 共用權限等級：：參閱 #### 檔案操作權限


#### 快速分享功能
- 適用範圍：資料夾與檔案均提供「分享」按鈕，方便對內溝通或發送外部協作連結
- 操作方式：點擊分享按鈕後，系統產生該項目的通用連結並自動複製到剪貼簿，同時顯示 Toast 提示「已複製分享連結」
- 連結格式：`{baseUrl}/share/{type}/{id}`，其中 `type` 為 `folder` 或 `file`，`id` 為該項目的唯一識別碼
- 權限限制：分享對象需具備該資料夾或檔案的存取權限，否則開啟連結時顯示「您無權瀏覽此項目，請聯繫管理員取得權限」
- 按鈕位置：資料夾列與檔案列操作欄中，位於收藏按鈕後方，使用 `fa-share-nodes` 圖示

#### UI 按鈕可見性規則（依權限等級隱藏）
- 使用者對某資料夾或檔案**不具備該操作所需權限**時，系統應**直接隱藏**對應的操作按鈕，而非顯示按鈕後由使用者點擊再提示「權限不足」。

- 此規則適用於所有檔案列表頁面的操作欄（含右鍵選單、「更多」下拉選單等）。
- 前台渲染時應依當前使用者對該項目的實際權限等級，動態決定哪些按鈕應顯示。

#### 最近資料夾存取邏輯 
- 檢視檔案時自動加入最近存取最前面（去重後 unshift）
- 最近存取上限 **20 筆**
- 初始資料 8 筆

#### UI 狀態
- Toast 通知：自動消失 2 秒，有一般 / 警告兩種樣式
- 上傳功能：已實作拖曳上傳 Modal，支援拖曳檔案或點擊選擇檔案

#### 資料儲存
- 全部使用 localStorage，key：`fileDatabase`、`recentFiles`、`favoriteFiles`、`trashFiles`、`favoriteFolders`、`sharedByMe`
- 每次載入頁面重新初始化假資料（`forceReinit = true`）

### 1.4 上傳與檔案管理（通用）

#### 上傳 Modal UI
- 點擊「上傳檔案」按鈕後彈出上傳 Modal
- Modal 包含：
  - 標題區：顯示上傳檔案」，右上角關閉按鈕
  - 拖曳上傳區：虛線框區域，支援拖曳檔案進入上傳，拖入時有視覺高亮效果
  - 來源按鈕：上傳檔案
  - 已選檔案列表：顯示檔名、檔案大小、副檔名圖示，可逐一移除
  - 底部：進度條（顯示已選/上限）+ 上傳按鈕（使用系統統一 `.btn.primary` 樣式）
- 點擊拖曳區或「上傳檔案」來源按鈕均可開啟檔案選擇器
- 超過上限時顯示 alert 提示

#### 上傳限制
- 單次上傳數量上限：**10 個檔案**
- 單檔大小上限：**10 MB**
- 允許上傳的副檔名（白名單）：

| 類別 | 允許副檔名 |
|------|-----------|
| 文件 | `.pdf`、`.doc`、`.docx`、`.xls`、`.xlsx`、`.ppt`、`.pptx`、`.txt`、`.csv` |
| 圖片 | `.jpg`、`.jpeg`、`.png`、`.gif`、`.bmp`、`.svg`、`.webp`、`.tiff` |
| 音訊 | `.mp3`、`.wav`、`.ogg`、`.m4a` |
| 影片 | `.mp4`、`.avi`、`.mov`、`.wmv`、`.webm` |
| 壓縮 | `.zip`、`.rar`、`.7z` |

- 不在白名單內的副檔名一律**禁止上傳**，並顯示提示訊息：「不支援此檔案格式，請確認後重新選擇」
- 副檔名驗證**不區分大小寫**（例如 `.PDF` 與 `.pdf` 視為相同）
- 存入資料庫時，副檔名一律**轉換為小寫**儲存（例如上傳 `報告.PDF` → 資料庫記錄副檔名為 `.pdf`）
- **禁止上傳**可執行檔（如 `.exe`、`.bat`、`.cmd`、`.sh`、`.msi`、`.dll` 等），以降低資安風險
- 檔名命名規則：
  - 最多 **255 個字元**（characters）
  - 支援 Unicode（中文、日文 等皆可）
  - 不可包含以下特殊字元：`\ / : * ? " < > |`
  - 不可為空字串
  - 不能只有空白字元

#### 上傳後行為
- 上傳後檔案出現位置：上傳完成後，自動重新整理當前所在資料夾的檔案列表，新檔案依排序規則顯示於列表中
- 上傳後排序規則：依現有列表排序規則（子資料夾優先，再依檔案名稱正排序）
- 重複檔名處理：上傳 Modal 提供「**覆蓋同名檔案**」勾選選項（預設未勾選）：
  - **勾選**（覆蓋模式）：若目標資料夾已存在相同檔名的檔案，以新上傳的檔案覆蓋舊檔（更新檔案內容與中繼資訊，保留原有 ID）。
  - **未勾選**（重新命名模式）：若目標資料夾已存在相同檔名的檔案，系統自動在原檔名後方（副檔名之前）附加時間戳記，格式為 `_YYYYMMDDHHmmssSSS`（年月日時分秒毫秒，共 17 碼）。例如：`報告.pdf` → `報告_20260304143025123.pdf`。
  - 若無同名檔案，則不論勾選與否皆直接新增，不做任何改名。

### 1.5 搜尋與篩選（通用）

#### 文件庫內搜尋
- 系統的全站搜尋必須納入**文件庫模組**內的資料，確保使用者能透過全站搜尋找到文件庫內容。
- 搜尋範圍包含：
  - **資料夾名稱**
  - **檔案名稱**
  - 檔案標籤
  - 檔案內容（若後端支援內容索引）
- 搜尋結果需遍循權限控制，使用者僅能看到有權限的項目。

### 1.6 UI 狀態（通用）

- 載入中：顯示等待畫面（Loading），提示使用者資料載入中
- 空狀態：顯示「無資料」提示畫面，告知使用者目前無可顯示的內容
- 錯誤狀態：顯示錯誤訊息提示，告知使用者操作發生問題
- 操作成功提示：顯示「執行成功」Toast 通知

### 1.7 檔案預覽機制（通用）

使用者點擊檔案時，依檔案類型決定預覽或下載行為：

| 檔案類型 | 行為 | 說明 |
|----------|------|------|
| PDF（.pdf） | 另開分頁預覽 | 使用瀏覽器原生 PDF 檢視器，於新分頁開啟 |
| 圖片（.jpg、.jpeg、.png） | 另開分頁預覽 | 於新分頁中直接顯示圖片 |
| 其他圖片（.gif、.bmp、.svg、.webp 等） | 直接下載 | 不支援線上預覽，需下載後檢視 |
| Word（.doc、.docx） | 直接下載 | 不支援線上預覽，點擊後觸發瀏覽器下載 |
| Excel（.xls、.xlsx） | 直接下載 | 不支援線上預覽，點擊後觸發瀏覽器下載 |
| PowerPoint（.ppt、.pptx） | 直接下載 | 不支援線上預覽，點擊後觸發瀏覽器下載 |
| 其他格式 | 直接下載 | 未列於上方可預覽類型的檔案，一律觸發下載 |

#### 補充說明
- 可預覽類型（PDF、圖片）：點擊後以 `window.open()` 或 `<a target="_blank">` 方式於新分頁開啟檔案 URL。
- 不可預覽類型（Word、Excel、PPT 及其他）：點擊後透過 `<a download>` 或後端回傳 `Content-Disposition: attachment` 觸發下載。
- 此規則適用於所有檔案列表頁面（近期存取、標籤、共享部門、我的文件等）。

### 1.8 組織架構與權限分享邏輯（通用）

#### 組織架構模型
- 組織圖（Org Chart）採用**樹狀結構（Tree）**，支援多層級部門節點。
- 每個部門節點可包含子部門與人員，層級數量不限。
- 權限與分享設定必須能依循此多層級部門結構進行指派。

#### 分享對象選擇
- 分享資料夾或檔案時，可依**部門**或**人員**進行選擇。
- 選擇部門時，提供「**全選**」功能，可一鍵勾選該部門下所有人員，提升操作友善度。
- 亦可在全選後，手動取消個別人員的勾選，進行細部調整。

#### 權限繼承規則
- 新增的資料夾或檔案，**預設繼承上層（父層）資料夾的權限設定**。
- 繼承後仍可針對該資料夾或檔案進行個別權限調整（覆寫）。
- 若上層權限變更，已被個別覆寫的子項目不受影響；未覆寫的子項目則同步更新。

#### 權限授與及拒絕存取機制
- 權限設定的粒度為**單一資料夾或單一檔案**，系統透過四級角色統一管理授與及拒絕：
  - **管理者（Admin）**：查看 / 編輯 / 上傳 / 下載 / 刪除
  - **編輯者（Editor）**：查看 / 編輯 / 上傳 / 下載
  - **檢視者（Viewer）**：查看 / 下載
  - **拒絕存取（Denied）**：全部禁止，強制排除該使用者對該項目的存取權限
- **優先順序**：拒絕存取優先於所有其他權限判斷。即使人員所屬部門已具備管理者 / 編輯者 / 檢視者角色，只要該人員被個別設定為「拒絕存取」，則**強制排除、不可見**。

#### 權限判斷流程

```
使用者請求存取資料夾/檔案
  │
  ├─ 該使用者是否被設定為「拒絕存取」角色？
  │    └─ 是 → 🚫 不可見（強制排除）
  │
  ├─ 該使用者（或所屬部門）是否被授予角色（管理者/編輯者/檢視者）？
  │    └─ 是 → ✅ 依角色等級存取
  │
  ├─ 該項目是否繼承上層權限？
  │    └─ 依上層權限設定判斷 → ✅ 或 🚫
  │
  └─ 無任何權限設定 → 🚫 預設不可見
```

### 1.9 外部連結分享機制（通用）

#### 內外網域設定
- 系統需支援**內網網域（Intranet Domain）**與**外網網域（Internet Domain）**兩組參數設定。
- 產生分享連結時，依據所選網域類型產生對應的 URL（內網連結 / 外網連結）。
- 若該部署環境**未設定外網網域**（即無外網環境），則：
  - 前台 UI 中「外網連結」相關的按鈕、輸入框、複製鏈結等元素需**隱藏或停用（disabled）**。
  - 僅保留內網連結的分享功能。
- 網域參數由後台管理設定，前台依 API 回傳的環境設定動態判斷是否顯示外網選項。

#### 外部連結分享限制（資安考量）
- 外部連結**僅限分享「單一檔案」**，不可分享整個資料夾。
- 若使用者嘗試對資料夾產生外部連結，應顯示提示訊息（例如：「基於資安考量，外部連結僅支援分享單一檔案」）並阻擋操作。
- 內網連結不受此限制，可分享資料夾或單一檔案。

#### 外部連結有效期限
- 產生外部連結時，使用者**必須設定有效期限**，不允許永久有效的外部連結。
- 可選有效期限：

| 選項 | 說明 |
|------|------|
| 1 天 | 即時性分享，雔日失效 |
| 3 天 | 短期分享 |
| 7 天 | 一週期限 |
| 14 天 | 兩週期限 |
| 30 天 | 一個月期限 |
| 自訂日期 | 使用者自行指定到期日（不得早於當日） |

- 連結到期後自動失效，外部人員點擊後顯示「此連結已過期或已停用」提示頁。
- 分享者可隨時手動停用尚未到期的連結。
- 內網連結不強制設定有效期限（預設永久有效），但可選擇性設定。

#### 分享連結彙整

| 連結類型 | 分享對象 | 可分享範圍 | 有效期限 | 條件 |
|----------|----------|------------|----------|------|
| 內網連結 | 內部人員 | 資料夾、單一檔案 | 預設永久（可選設） | 系統預設提供 |
| 外網連結 | 外部人員 | **僅限單一檔案** | **必填**（1/3/7/14/30天或自訂） | 需後台設定外網網域；未設定時隱藏 |

### 1.10 資料儲存與刪除機制（通用）

#### 檔案儲存架構
- 實體檔案**絕對不可存入資料庫（SQL）**。
- 資料庫容量有限（常見上限 1GB 或 10GB），儲存檔案將快速耗盡空間並影響系統穩定性。
- 檔案必須存放於**外部儲存空間**，包括但不限於：
  - 檔案伺服器（File Server）
  - 雲端物件儲存（如 Azure Blob Storage、AWS S3、MinIO 等）
  - NAS / SAN 等網路儲存裝置
- **實體檔案以 GUID 命名儲存**，原始檔名僅記錄於資料庫中：
  - 上傳時系統產生唯一 GUID（如 `a3f1b2c4-5678-9def-0123-456789abcdef`）作為實體檔名
  - 實體儲存路徑範例：`/storage/a3f1b2c4-5678-9def-0123-456789abcdef`
  - 原始檔名（如 `員工手冊_2025.pdf`）存入資料庫 `files.name` 欄位
  - 下載或預覽時，系統依資料庫記錄的原始檔名回傳給使用者
- 資料庫中僅儲存檔案的**中繼資訊（Metadata）**，包括：
  - 檔案名稱、大小、格式、上傳者、上傳時間、更新時間
  - 檔案在外部儲存空間的 GUID 識別碼（Storage Key）
  - 標籤、權限、所屬資料夾等關聯資訊

#### 刪除機制（軟刪除 + 垃圾桶）
- **禁止立即真實刪除（Hard Delete）**，以防範使用者誤刪或惡意操作風險。
- 所有刪除操作一律採用**軟刪除（Soft Delete）**：
  - 檔案/資料夾標記為「已刪除」狀態，並移入垃圾桶。
  - 實體檔案與資料庫紀錄均**不立即移除**。
  - 前台列表中不再顯示已軟刪除的項目（查詢時過濾 `is_deleted = false`）。
- **垃圾桶保留期限**：30 天（與 1.1 垃圾桶規格一致）。
- 垃圾桶中的項目可執行：
  - **還原**：恢復至原位置，清除刪除標記。
  - **永久刪除**：經二次確認後，同時刪除資料庫紀錄與外部儲存空間的實體檔案。
- 過期自動清理：系統排程定時掃描垃圾桶，超過 30 天的項目自動執行永久刪除。

#### 設計理由
- **檔案不入 DB**：避免資料庫膏脹、備份困難、效能下降；外部儲存可彈性擴充容量。
- **軟刪除**：提供安全網，保護使用者免於誤操作造成不可逆的資料損失；同時可因應稽核或合規需求保留刪除紀錄。
