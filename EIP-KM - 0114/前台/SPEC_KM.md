### 2.7 文章編輯器（km-editor.html）

> 用於新增及編輯 KM 知識庫文章。

#### 表單欄位

| 欄位 | 必填 | 說明 |
|------|------|------|
| 文章標題 | ✅ | 最多 **30 字**；列表顯示時超過 25 字以「…」截斷 |
| 文章分類 | ✅ | 下拉選單，選項由**後台維護**（可新增/刪除）；預設分類包括：公告通知、規範辦法、SOP 流程、技術文件、教育訓練、專案相關、其他 |
| 所屬部門 | ✅ | 下拉選單，**必填**（因審核流程需指定審核人員）；部門清單**自動同步組織圖**（後台「組織圖設定」維護），前台不可自行新增部門 |
| 文件效期 | 否 | 選項：永久有效（預設）/ 一年 / 六個月 / 自訂到期日 |
| 文章標籤 | 否 | 自由輸入，按 Enter 新增；輸入時**自動建議已存在的標籤** |
| 文章內容 | ✅ | 富文字編輯器（Rich Text Editor） |
| 附件上傳 | 否 | 拖曳或點擊上傳 |
| 編輯語言 | 否 | 繁體中文（預設）/ English / 日本語 |

#### 文件效期規則
- 自訂到期日限制：最早為**明天**，最長為**3 年**
- 到期行為：系統**自動下架**（不可瀏覽），並**通知作者**
- 失效文章在作者的「個人貢獻 → 失效」列表中可查看

#### 標籤規則
- 每篇文章最多 **10 個**標籤
- 單一標籤字數上限：**10 字**
- 標籤輸入方式：自由輸入 + 自動建議已存在標籤
- 重複標籤判斷：同一篇文章不可加入相同標籤

#### 附件上傳規則
- 單檔大小上限：**10 MB**（對齊文件庫通用規則）
- 附件數量上限：**10 個**
- 允許的副檔名（對齊文件庫通用白名單）：

| 類別 | 允許副檔名 |
|------|-----------|
| 文件 | `.pdf`、`.doc`、`.docx`、`.xls`、`.xlsx`、`.ppt`、`.pptx`、`.odt`、`.ods`、`.odp`、`.txt`、`.csv`、`.rtf` |
| 圖片 | `.jpg`、`.jpeg`、`.png`、`.gif`、`.bmp`、`.svg`、`.webp`、`.tiff` |
| 音訊 | `.mp3`、`.wav`、`.ogg`、`.m4a` |
| 影片 | `.mp4`、`.avi`、`.mov`、`.wmv`、`.webm` |
| 壓縮 | `.zip`、`.rar`、`.7z` |

- 不在白名單內的副檔名一律禁止上傳，提示「不支援此檔案格式」
- 禁止上傳可執行檔（`.exe`、`.bat`、`.cmd`、`.sh`、`.msi`、`.dll` 等）

#### 富文字編輯器功能
- 支援：粗體、斜體、底線、刪除線
- 標題：H1（對應 H2 tag）、H2（對應 H3 tag）、段落
- 列表：無序列表、有序列表
- 插入：連結、圖片（URL）、引用區塊、程式碼區塊
- 對齊：靠左、置中、靠右
- 操作：復原、重做
- 文章內容字數上限：**10,000 字**

#### 發佈流程
- 文章發佈後**需經審核通過才能上線**
- 審核流程為**單級審核**（一人審核即可）
- 發佈必填驗證：文章標題、文章分類、文章內容缺一不可
- 發佈成功後導回知識總覽頁面

#### 草稿機制
- 支援手動儲存草稿
- 手動儲存草稿後，顯示 Toast「草稿已儲存，即將前往草稿管理…」，**1.2 秒後自動導向 `km-manage.html#draft`**（草稿分頁）
- 支援**自動儲存草稿**，間隔 **30 秒**（自動儲存**不觸發頁面跳轉**）
- 自動儲存採用 **dirty flag 機制**：僅在標題、分類、部門、效期或文章內容**實際變更**時才觸發存檔，無變更時不發送請求
- 變更偵測方式：對表單欄位監聽 `input` / `change` 事件，比對快照（snapshot）判斷是否有差異
- 自動儲存後在底部顯示「自動草稿儲存完成於 YYYY/MM/DD HH:mm:ss」
- 離開頁面時若有未儲存的內容，需 confirm 確認
- `km-manage.html` 支援 URL hash 參數（如 `#draft`），載入時自動切換至對應分頁

#### 編輯已發佈文章
- 已發佈的文章**可編輯**
- 編輯儲存後需**重新送審**，審核通過才更新線上版本
- 系統**保留歷史版本**，支援查看與**回滾**

#### 多語言編輯
- 同一篇文章可**分別編輯多語系內容**（繁體中文 / English / 日本語）
- 前台切換語系時，顯示對應語言版本的文章內容
- 若該語系尚無內容，顯示預設語系（繁體中文）的內容

#### 文章權限控制
- 作者可自行設定文章可見範圍：
  - **公開**：全公司可見
  - **部門**：僅所屬部門成員可見
  - **指定人員**：僅指定的人員可見
- 附件下載權限：**同文章閱讀權限**（能看文章就能下載附件）

### 2.10 KM 列表頁通用樣式

> 適用於所有 KM 功能模組的列表式頁面（最新文章、熱門文章、收藏、管理等）。  
> 各頁面不另建專屬樣式，統一套用以下規範。

#### 頁面佈局
- 返回列：`margin-bottom: var(--spacing-element)`
- 頁面標題 `h2`：`font-size: var(--font-page-title)`、`font-weight: 700`、`margin-left: 14px`
- 所有內容區塊（篩選列、統計、列表卡片、分頁）左側對齊 `margin-left: 14px`
- 容器 `.km-container` 設為 `overflow: visible`，確保卡片陰影不被裁切

#### 篩選列
- 篩選標籤：`font-size: var(--font-body-small)`、`color: var(--text-muted)`、`font-weight: 600`
- 下拉選單：
  - `font-size: var(--font-body-small)`
  - `padding: 8px 32px 8px 14px`
  - `border: 1px solid var(--border-color)`、`border-radius: var(--radius-sm)`
  - 自訂下拉箭頭（SVG chevron），原生外觀隱藏
  - `:focus` 邊框色：`var(--primary-color)`
- 此下拉選單樣式為**全 KM 模組通用**，分頁區的每頁筆數選單亦套用相同樣式

#### 結果統計列
- `font-size: var(--font-body-small)`、`color: var(--text-muted)`
- 筆數數字加粗：`color: var(--text-primary)`

#### 列表卡片容器
- 對齊總覽頁 `.km-block` 樣式：
  - `background: #fff`
  - `border: 1px solid rgba(0, 0, 0, .125)`
  - `border-radius: .25rem`
  - `box-shadow: rgba(176, 184, 214, 0.09) 0px 10px 10px 20px, rgb(176, 184, 214) 10px 10px 15px -5px`
  - `overflow: hidden`

#### 列表項（文章列）
- 佈局：`display: flex`、`align-items: flex-start`、`gap: 14px`
- 內距：`padding: 16px`（左右含額外 16px 使內容縮排）
- 分隔線：使用 `::after` 偽元素，`left: 16px`、`right: 16px`，與卡片左右邊框保持距離
- 最後一筆無分隔線
- Hover 背景：`#F3F4F6`，填滿整列（不受分隔線縮排影響）
- 點擊：跳轉 `km-article.html?id={articleId}`

#### 文章縮圖（選填）
- 位置：列表項**左側第一個元素**
- 尺寸：`90px × 68px`、`border-radius: 0`（無圓角）
- 邊框：`1px solid var(--border-color)`
- 無圖片時顯示灰底 + image icon placeholder
- 文章資料可透過 `noThumb: true` 標記為不顯示縮圖

#### 文章標題
- `font-size: var(--font-card-title)`、`font-weight: 600`、`color: #1E293B`
- 單行截斷：`overflow: hidden; text-overflow: ellipsis; white-space: nowrap`
- Hover 變色：`color: var(--primary-color)`

#### 分類標籤
- 位於文章標題下方 meta 列**最左側**
- 樣式：`background: #4B5563`（深灰底）、`color: #fff`（白字）
- `font-size: var(--font-label)`、`padding: 1px 8px`、`border-radius: 3px`
- 無邊框
- 分類選項對齊編輯器：公告通知、規範辦法、SOP 流程、技術文件、教育訓練、專案相關、其他

#### Meta 資訊列
- 位於標題下方，`margin-top: 6px`
- `font-size: var(--font-body-small)`、`color: #7F7F7F`
- 順序：分類標籤 → 發佈者（user icon）→ 單位（building icon）→ 瀏覽數（eye icon）
- icon `font-size: 12px`、`color: var(--text-muted)`

#### 文章摘要
- `font-size: var(--font-body-small)`、`color: #7F7F7F`、`margin-top: 6px`
- 單行截斷，最多約 80 字

## 四、系統架構與未來規劃

### 4.1 SaaS 與地端參數設計

#### 部署模式
- 系統必須同時支援兩種部署情境：
  - **SaaS（雲端服務）**：多租戶共用基礎建設，透過參數區分各租戶配置。
  - **地端（On-Premises）**：賣斷給客戶自行架設，參數由客戶自行管理。
- 所有與環境相關的設定（網域、容量、功能開關等）均透過**參數化設定**管理，不寫死於程式碼中。

#### 空間容量（Quota）管理
- 系統必須具備以下容量上限參數，供後台管理設定：

| 參數 | 說明 | 預設值 |
|------|------|--------|
| 總體空間上限 | 整個系統（或單一租戶）可使用的儲存總量 | <!-- TODO: 待定義 --> |
| 部門空間上限 | 單一部門資料夾可使用的儲存上限 | <!-- TODO: 待定義 --> |

- 當使用量接近上限時，前台應顯示警告提示（例如用量達 80% / 90% 時）。
- 達到上限時，禁止上傳新檔案，並顯示明確的錯誤訊息。
- Quota 參數由後台管理介面設定，前台透過 API 讀取並在 UI 中展示用量狀態。

### 4.2 開發優先順序

#### 開發階段規劃

| 階段 | 模組 | 說明 |
|------|------|------|
| **Phase 1** | 文件庫 | 優先完成文件庫樸心功能（上傳、瀏覽、權限、分享、垃圾桶等） |
| **Phase 2** | 封裝 App | 將系統封裝為行動端應用，採整合方式（見下方說明） |
| **Phase 3** | KM（知識管理） | 建置知識總覽、分享中心、AI 加值等功能 |

#### App 封裝策略
- **不採用**獨立上架 App Store 的方式（審核嚴格、退件率高、維護成本高）。
- 傾向研究以下整合方式：
  - 與**企業通訊軟體**整合（如 LINE WORKS、Microsoft Teams、企業內部 App 等）
  - 與現有**電子表單（BPM）系統**整合，將文件庫功能嵌入既有業務流程
  - WebView / PWA 等輕量化封裝方式
- 具體整合方案待評估後確認。
